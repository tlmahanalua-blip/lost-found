# База для Assignment 3: что изменилось

## Совместимость с твоим отчётом

Основные таблицы теперь используют имена и связи из твоего Assignment 3:

- **users**: user_id (INTEGER PRIMARY KEY), display_name, email, password_hash, role.
- **categories**: category_id (INTEGER PRIMARY KEY), category_name.
- **items**: item_id (INTEGER PRIMARY KEY), user_id (FOREIGN KEY), category_id (FOREIGN KEY), report_number, title, description, location, event_date, report_type и status.
- **report_type** хранит lost/found; **status** хранит open/resolved, как в твоём SQL. На сайте resolved показывается как Returned.
- Для одного пользователя номер report_number уникален. Один пользователь может иметь много объявлений; одна категория может относиться ко многим объявлениям.

Точный исходный SQL трёх таблиц из отчёта находится в database/assignment3-core.sql. Полная схема веб-приложения — database/schema.sql. Дополнительные таблицы нужны для сессий, фотографий, заявок и жалоб; это расширение проекта, которое следует отразить в change log.

Поле времени event_time добавлено отдельно: при создании объявления можно указать время потери или находки. У старых объявлений неизвестное время не выдумывается.

## Твои существующие данные сайта

При первом запуске версии 3 сервер узнает схему предыдущей версии 2 и переносит данные в новую схему в одной транзакции. Имена и хеши паролей, фотографии, контакты, заявки и действующие сессии сохраняются. Внутренние ID становятся числовыми; старую страницу нужно обновить.

Перед локальным переносом создаётся полная согласованная копия SQLite: **data/lost-found.db.before-v3.backup.db**. При ошибке транзакция откатывается. Для удалённой базы перенос транзакционный, но локальная резервная копия не создаётся; используй резервирование/экспорт своего провайдера.

Работу переноса проверяли на искусственных копиях версии 2.0 и 2.1. Твой загруженный файл my_lost_found.sqlite.db..db теперь проверен: 10 пользователей, 10 категорий, 102 объявления, целостность OK, нарушений FOREIGN KEY нет. Импорт всех 102 записей и повторный импорт проверены в тестовой базе вместе с сохранением существующего входа. Исходный файл не изменён. На твоём ноутбуке перенос выполнится после запуска обновления.

## Подключить твою учебную базу из Assignment 3

Загруженный файл уже включён в частный архив как **database/assignment3-original.db**. При запуске **UPDATE-WINDOWS.cmd** или **npm.cmd start** он импортируется автоматически один раз. Повторный запуск не создаёт дубликатов.

Для другого файла базы можно выполнить ручной импорт:

1. Останови сервер сайта.
2. В распакованной папке проекта дважды нажми **IMPORT-ASSIGNMENT3.cmd**.
3. Вставь полный путь к старому файлу базы и нажми Enter.
4. После сообщения Imported запусти сайт снова и обнови страницу.

Импорт читает исходный файл без его изменения. Данные добавляются в текущую базу сайта. Существующий аккаунт с совпадающим email сохраняет своё имя, пароль и права; повторный импорт того же содержимого не создаёт дубликаты. Для импорта выбранного файла с обновлённым содержимым требуется отдельная сверка, чтобы не продублировать изменённые записи.

Учебные записи помечаются **Sample**. Импортированные пользователи получают роль student; права координатора для своего аккаунта задавай через ADMIN_EMAILS. Хеши старых паролей сохраняются, но вход работает только для поддерживаемого формата scrypt. В загруженном файле все 10 старых значений password_hash имеют неподдерживаемый формат. Вход под ними не включён; автоматического сброса паролей нет. Текущий аккаунт сайта сохраняется, а новые аккаунты создаются через Create account с scrypt-хешированием.

Если источник уже является текущей базой сайта, импорт остановится: переносить базу саму в себя не требуется.

## Отдельный пример 10 / 10 / 100

В архив включён **database/assignment3-demo.db**: новая демонстрационная база с 10 вымышленными пользователями, 10 категориями и 100 объявлениями. Это НЕ твоя исходная база и НЕ ответы опроса.

Она имеет три таблицы исходного Assignment 3. Для демонстрации её можно открыть в DB Browser for SQLite или добавить записи в сайт командой:

```
npm.cmd run db:seed
```

Эта команда добавляет Sample-записи, не удаляя существующие аккаунты и объявления. Повторный запуск не дублирует их. Учебные логины: student1@example.invalid — student10@example.invalid, пароль **Demo-only-2026!**. Эти вымышленные аккаунты нужны только для локальной демонстрации; не загружай учебную базу в публичный пилот с реальными пользователями.

## Резервная копия для B3

Останови сайт, затем выполни:

```
npm.cmd run db:backup
```

Команда создаёт согласованную локальную копию с датой в имени. Для восстановления локальной базы останови сайт и восстанови выбранную копию в data/lost-found.db; исходный файл перед этим сохрани отдельно. Не выполняй восстановление поверх работающего сервера.

## Что показать преподавателю

1. В DB Browser: users, categories, items и их PRIMARY KEY / FOREIGN KEY.
2. Запрос количества записей и группировки по категории — database/defense-queries.sql.
3. В интерфейсе: чтение списка объявлений и запись нового объявления, затем новую строку в таблице items.
4. Хеш password_hash и параметризованный INSERT в api/index.js.
5. Реальный файл резервной копии и шаг восстановления.

Пункты о публичном размещении, подтверждении университетской почты, редактировании объявления, модерации и мультимедиа остаются отдельными следующими задачами. Эта версия закрывает именно согласование структуры базы, перенос и время события; завершение всех Assignment 3/4 не заявляется.

## Удаление объявления в версии 3.2

Delete report доступно автору и администратору. Сервер проверяет права, затем удаляет запись в транзакции; FOREIGN KEY ON DELETE CASCADE удаляет связанные фотографии, заявки и жалобы. Аккаунт пользователя сохраняется. Отдельная таблица id_counters хранит последний номер ID, чтобы старый адрес удалённой вещи не начал показывать другую вещь. Это дополнительная служебная таблица; исходные три таблицы Assignment 3 сохраняют свои связи.

Удалённый учебный пример не появляется снова при повторном импорте того же источника. Сам исходный файл Assignment 3 и ранее сделанные резервные копии не меняются.
